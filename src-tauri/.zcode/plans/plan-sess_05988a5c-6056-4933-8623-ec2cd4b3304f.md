**Objetivo:** convertir las debilidades *"observabilidad"* y *"startup sin UI de error"* en una fortaleza verificable, sobre la cual las siguientes etapas (ventana nativa, onboarding, NSIS, updater) se apoyan con confianza.

**Principio:** 100% aditivo. Cero cambios que rompan el contrato IPC existente, cero migraciones destructivas, cero retiro de código.

`diagnostics_export_report` arma un zip con: `notias.log` (último), `crash.log` (último si existe), `notias.meta`, salida de `diagnostics_snapshot` serializada a JSON, y `manifest.txt` con timestamp + versión + OS. Devuelve la ruta absoluta al zip creado.

#### A3. `lib.rs` — convertir startup en "graceful bootstrap"

Reemplazar la cadena de `.expect()` (líneas 34-48) por una función que devuelve `Result<AppBootstrap, AppError>`:

```rust
struct AppBootstrap {
    state: AppState,
    startup_error: Option<StartupError>, // Some = algo falló, mostrar UI de error
}

fn bootstrap() -> AppBootstrap { /* reemplaza los .expect() por match/ok() */ }
```

- Si `AppPaths::new()`, `db::open`, `db::verify` fallan → `state` se llena parcialmente (paths sí, conn no) y `startup_error = Some(...)`.
- En `run()` final, **antes** de `tauri::Builder`, registrar el comando `startup_error` y solo construir `AppState` con el `db` envuelto en `Option<Mutex<Conn>>` (o más simple: si no hay conn, los comandos que la usen devuelven un error claro y la UI muestra la pantalla de error).
- Si todo va bien → comportamiento idéntico al actual. **Si todo va mal** → la app abre igual con una pantalla de error de pantalla completa en vez de crashear.

Esto requiere cambiar la firma de `AppState.db` a `Option<Mutex<Connection>>` y adaptar **todos** los callers. La lista de callers es finita (~45 comandos) y los cambios son mecánicos (`state.db.lock().expect("db lock")` → `state.db.as_ref().ok_or(AppError::DbUnavailable)?.lock()`). Lo automatizo con `grep -l 'state.db.lock'` antes de empezar.

`panic_hook::install(&paths.logs_dir)` se llama antes del `bootstrap()` (los logs ya tienen un destino incluso si bootstrap falla). El subscriber de tracing se inicializa primero; el panic hook después.

#### A4. Wiring en `lib.rs::run()`

```rust
pub fn run() {
    // 1. Tracing a disco
    let paths_for_logs = AppPaths::new().ok();
    if let Some(ref p) = paths_for_logs {
        let _ = diagnostics::log_setup::init(p);
    } else {
        let _ = tracing_subscriber::fmt()... // fallback como el actual
    }
    // 2. Panic hook (lo antes posible, antes del bootstrap)
    if let Some(ref p) = paths_for_logs {
        diagnostics::panic_hook::install(&p.logs_dir);
    }
    // 3. Bootstrap robusto
    let boot = bootstrap();
    // 4. Builder con state + nuevo módulo de comandos
    tauri::Builder::default()
        .plugin(tauri_plugin_fs::init())
        .plugin(tauri_plugin_dialog::init())  // NUEVO — para "Save report as…"
        .manage(boot.state)
        .invoke_handler(tauri::generate_handler![
            // ...todos los existentes...,
            diagnostics::commands::*,
        ])
        .setup(|app| {
            // Si hubo startup_error, emitir evento para que el frontend muestre la pantalla
            if let Some(err) = boot.startup_error {
                let _ = app.emit("notias:startup-error", err);
            }
            Ok(())
        })
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

Dependencias nuevas en `Cargo.toml`: `tauri-plugin-dialog = "2"` (añadir también el permission `dialog:default` en `capabilities/default.json`).
